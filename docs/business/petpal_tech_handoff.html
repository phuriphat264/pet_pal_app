02 — Key Flows

เส้นทางการทำงานหลัก 3 เส้นทาง

A. Authentication — รองรับ email/password และ social login

1

Client ส่ง credential

Email+password ตรง หรือ ID token จาก Google / access token จาก Facebook

2

Backend ตรวจสอบ

Google: verify ผ่าน google.oauth2.id_token เทียบ audience กับ GOOGLE_CLIENT_ID · Facebook: cross-check debug_token กับ app ID ของเราเอง (กัน token ของแอปอื่นมาสวมรอย)

3

ออก JWT

Access token อายุ 30 นาที + refresh token อายุ 14 วัน

!

Rate limit ที่ /auth

จำกัด 10 คำขอ/60 วิ ต่อ IP กัน brute-force — เก็บ state ใน memory เครื่องเดียว (ดูหัวข้อ 04)

B. Booking-gated Camera Access — ลูกค้าดูกล้องได้เฉพาะโรงแรมที่จองอยู่จริง

1

Client ขอ GET /cameras/{id}/stream

ส่ง JWT มาด้วยตามปกติ

2

ตรวจสิทธิ์ตาม role

Admin/Technician ผ่านทันที · Customer ต้องมี booking ที่ hotel_id เดียวกับกล้อง และสถานะไม่ใช่ cancelled

3

ถอดรหัสรหัสผ่านกล้อง

Fernet-encrypted password ที่เก็บใน DB ถูก decrypt ฝั่ง server

!

ส่ง URL กลับไปยัง client

rtsp://user:pass@ip:port/path — credential หลุดไปถึง client ตรงๆ ยังไม่ผ่าน proxy/token แบบ short-lived (ดูหัวข้อ 04)

C. AI Smart Match — ค้นหาโรงแรมด้วยข้อความอิสระ + AI enrichment แบบ async

1

Vector search ทันที

แปลงข้อความเป็น embedding (multilingual, รองรับไทย) ค้นด้วย pgvector ได้ผลลัพธ์กลับทันที

2

ส่งผลลัพธ์ local ก่อน

ตอบ client ทันทีพร้อม isFallback: true — ไม่ต้องรอ AI

3

Enrich ด้วย Gemini แบบ background

Async task จำกัด concurrency (semaphore 3), timeout 8 วิ, เขียนผลลง Redis (match_job:<id>, TTL 5 นาที)

4

Client poll ผลลัพธ์

GET /api/match/status/{job_id} จนกว่าจะ ready หรือ fallback ต่อ

03 — Test Coverage

สถานะการเทสปัจจุบัน

รันด้วย pytest (backend) และ flutter test (client) — ยังเป็น manual run, ไม่มี CI

04 — Known Gaps

สิ่งที่ทีม Tech Support ควรรู้ก่อนรับช่วงต่อ

แจ้งตรงๆ ไว้ก่อน เพื่อให้ทีมที่มาซัพพอร์ตวางแผนช่วยแก้ต่อได้ถูกจุด ไม่ใช่ต้องมาไล่เจอเอง

🔴 Gemini model deprecated

backend/app/gemini_client.py:11 ตั้งค่า MODEL_NAME = "gemini-2.0-flash" ซึ่งถูกยกเลิกไปแล้วตั้งแต่ 1 มิ.ย. 2026 — ฟีเจอร์ AI Smart Match enrichment น่าจะเรียก API แล้ว fail อยู่ตอนนี้ ต้องเปลี่ยนเป็น gemini-2.5-flash-lite (ราคาเท่าเดิม)

🟠 RTSP credential หลุดถึง client

_build_stream_url ใน cameras.py ส่ง rtsp://user:pass@ip:port ตรงให้แอป — ยังไม่มี edge-server proxy หรือ short-lived token ตามสถาปัตยกรรมเป้าหมาย

🟠 กล้องดูได้เฉพาะใน WiFi โรงแรม

RTSP URL เป็น LAN IP — ลูกค้าที่ไม่ได้อยู่ในโรงแรมเชื่อมต่อไม่ได้เลย ต้องมี edge/Mini Hub ต่อโรงแรมถึงจะแก้ได้จริง (ไม่ใช่แค่เพิ่ม bandwidth)

🟠 ไม่มี CI

เทสที่มีอยู่ (~24 ไฟล์รวมสองฝั่ง) ไม่ได้รันอัตโนมัติเลยตอน push/PR — ต้องรัน pytest / flutter test มือทุกครั้ง

🟡 Rate limiter เป็น in-memory เดี่ยว

core/rate_limit.py เก็บ state ในหน่วยความจำเครื่องเดียว — ใช้ได้ตราบใดที่ backend มี instance เดียว ถ้าจะ scale แนวนอนต้องย้ายไป Redis ก่อน (Redis มีอยู่แล้วในระบบ)
